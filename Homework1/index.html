STATISTICS HOMEWORKS / HOMEWORK 01

From Private Key to Public Key

Elliptic-curve scalar multiplication and a simple statistical exploration using a toy curve.

01Theoretical Background

Public-key cryptography makes it possible to calculate a public key from a private key without revealing the secret number. Ethereum uses elliptic-curve cryptography with a curve called secp256k1. The operation is written as Q = kG, where k is the private key, G is a fixed starting point, and Q is the resulting public point. On a secure curve, calculating Q is straightforward, while finding k from Q is computationally difficult.

This exercise uses a much smaller curve to make the calculations easier to follow. The equation is y² = x³ + 7 (mod 17), and the starting point is G = (1, 5). The expression “mod 17” means that the remainder after division by 17 is used. For example, 20 mod 17 equals 3. The point (1, 5) is valid because both sides of the curve equation give a remainder of 8.

Scalar multiplication does not mean multiplying the x and y coordinates by k. Instead, the point G is added to itself using special elliptic-curve rules. When two different points are added, the slope is calculated using their coordinate differences. When the same point is added to itself, a different formula called point doubling is used. Division is replaced by modular inverses, and the resulting coordinates are reduced modulo 17. The special point O, called the point at infinity, acts as the identity element.

03Statistical Exploration

The second part of the experiment looks at how the public points behave when the private key changes. Instead of considering only k = 6, the program examines the distinct finite points generated by the selected base point before the sequence starts repeating. This matters because repeatedly counting the same points would give a misleading picture of their distribution. The order of the base point indicates after how many additions the point at infinity is reached.

04Interpretation & Conclusion

Distribution and apparent uniformity. The frequency charts can show whether the observed coordinate values appear balanced, but perfect uniformity is not expected. Only pairs satisfying the elliptic-curve equation are allowed, and a chosen base point may generate only a small subgroup. In such a small example, repeated values and uneven frequencies are easy to notice. These observations describe the toy curve rather than proving anything about a real cryptographic system.

Correlations between input and output. The relationship between k and Q is deterministic: using the same private key and base point always gives the same public point. There is also a mathematical structure behind the outputs, since (k₁ + k₂)G = k₁G + k₂G. As a result, the points are not independent random values, even when the coordinate sequence looks irregular. This structure is essential to elliptic-curve cryptography.

Avalanche-like behaviour. The bit-flip experiment shows that changing a single input bit can change several bits of the resulting coordinates. This resembles the avalanche effect often discussed for hash functions, but elliptic-curve scalar multiplication is not designed to satisfy a fixed avalanche percentage. The Hamming distances observed here depend on the chosen encoding and the small curve, so they should not be interpreted as a security score.

One-way functions and cryptographic hashes. Both elliptic-curve scalar multiplication and cryptographic hashing involve calculations that are easy in the forward direction and difficult to reverse under appropriate conditions. However, they have different purposes. Secure elliptic-curve cryptography relies on the difficulty of the elliptic-curve discrete logarithm problem and supports public-key operations and digital signatures. Cryptographic hash functions are also designed around properties such as preimage resistance, second-preimage resistance and collision resistance. Collision resistance is not the purpose of the map k → kG within a correctly selected scalar range.

Conclusion. The experiment shows how a private scalar produces a public point through repeated elliptic-curve addition. The step-by-step calculations explain the basic operation, while the frequency, bit and Hamming-distance tables make it possible to compare several outputs. The curve modulo 17 is useful for learning, but it is not secure: its small number of points makes it easy to test possible private keys. Real Ethereum cryptography uses a much larger curve to avoid this problem.
