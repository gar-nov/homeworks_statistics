STATISTICS HOMEWORKS / HOMEWORK 03

Encryption, Decryption and Cryptanalysis

A comparison of a restricted-key elliptic-curve scheme and the Caesar cipher, with experiments on key recovery and letter statistics.

01Background and encryption methods

Encryption transforms a readable message into ciphertext, while decryption recovers the original message using the appropriate key. This homework considers two very different approaches: a simplified elliptic-curve encryption scheme and the classical Caesar cipher. Both can be demonstrated with small inputs, but their mathematical operations and security assumptions are not the same.

Introducing the toy cryptographic scheme

This experiment uses a simplified elliptic-curve ElGamal scheme built on secp256k1. A deliberately small private-key range makes the key-generation, encryption, decryption and key-recovery procedures practical to explore. The construction is intended for educational demonstrations, not for protecting real messages.

Elliptic-curve encryption on secp256k1

The scheme starts with the relationship Q = kG, where k is a private scalar, G is a fixed generator and Q is the public point. Here the arithmetic is performed on the actual secp256k1 curve, but the private scalar is deliberately restricted to the range 1–128. The small range makes a search attack practical; it does not make secp256k1 itself a small curve.

secp256k1: y² ≡ x³ + 7 (mod p)   |   Q = kG

For this exercise, an elementary form of elliptic-curve ElGamal is used. Each UTF-8 message byte b is represented by the point M = (b + 1)G. For each byte, a new random temporary scalar r is selected and the ciphertext consists of two curve points. Decryption removes the shared point using the recipient's private scalar.

Encryption: C₁ = rG   ·   C₂ = M + rQ
Decryption: M = C₂ − kC₁

The public key Q is used to encrypt; the private key k is required to decrypt. The temporary scalar r should be unpredictable and never reused in a secure design. Here it is also restricted to 1–128 to keep the experiment small. This is a custom teaching scheme, not Ethereum's standard transaction encryption mechanism and not a secure messaging protocol. Encoding bytes as small multiples of G is particularly inefficient and allows additional attacks.

Caesar cipher

The Caesar cipher shifts each letter by a fixed number of positions in the alphabet. With A = 0 through Z = 25, encryption adds the shift s modulo 26, and decryption subtracts it. Spaces and punctuation remain unchanged in this implementation, and lowercase letters remain lowercase.

Encryption: c = (m + s) mod 26
Decryption: m = (c − s) mod 26

The Caesar key is a single shift from 0 to 25. It is a symmetric cipher, because the same shift is needed for encryption and decryption. In contrast, elliptic-curve ElGamal uses a public/private key pair and point arithmetic.

03Statistical cryptanalysis of Caesar

English letters do not occur equally often. For example, E and T are relatively common, while Q and Z are rare. A Caesar shift moves the positions of these frequencies without changing their counts. This makes the key recoverable from sufficiently long English ciphertext by testing each possible shift and comparing the resulting letter frequencies with reference English frequencies.

Key recovery by chi-square scoring

The algorithm decrypts the ciphertext under all 26 possible shifts. For each candidate plaintext, it counts the letters A–Z and computes a chi-square discrepancy against standard English letter frequencies. The candidate with the smallest score is selected. This is statistical inference, not a guarantee: short messages and unusual vocabulary may produce misleading frequencies.

χ²(s) = Σ [ (observedᵢ(s) − expectedᵢ)² / expectedᵢ ],   expectedᵢ = N × pᵢ

The attack does not need to know the original shift. Longer English ciphertext generally gives a more reliable estimate.

04Restricted-key attack on ECC

Knowing the public point Q = kG, an attacker can test the permitted private keys one by one: compute G, 2G, 3G, and so on, and stop when the result equals Q. Because this homework restricts k to 128 possibilities, the search is very small. Once the correct k is found, the attacker can decrypt the ciphertext pairs with the same formula used by the legitimate recipient.

For k′ = 1, 2, …, 128: compute k′G; if k′G = Q, then k′ is the private key.
Encrypt a message first, then run the key-space attack.
Attack propertyObservation

The attack exploits the restricted private-key space, not a defect in the secp256k1 curve. A properly generated secp256k1 private key is selected from a range of approximately 2²⁵⁶ values, so testing all keys is computationally infeasible. General elliptic-curve discrete-logarithm attacks, such as Pollard's rho, still require on the order of 2¹²⁸ group operations for the full-size curve, which is beyond practical reach.

This example also has a separate design weakness: each message byte is mapped to one of only 256 known points. With the small temporary-scalar range, an attacker could enumerate r from C₁ = rG and remove rQ from C₂, even without recovering k. Secure encryption requires both a strong key space and an appropriate, reviewed encryption construction; a large curve alone is not enough.

What the experiments show

Caesar encryption preserves the relative frequencies of letters because every occurrence of the same plaintext letter is replaced by the same ciphertext letter. This gives the statistical attack a useful signal. With short samples, random fluctuations in the observed frequencies can overwhelm the reference distribution; with longer representative English samples, the correct shift is more likely to receive the lowest score.

The ECC attack uses a different kind of information. It does not need language frequencies: it compares calculated public points against a known public key. Its success follows from the tiny search space. Even a very long message would not make a 128-value private key difficult to enumerate. Conversely, a sufficiently large and uniformly selected private key prevents this direct exhaustive search, although the surrounding encryption design must also be secure.

Exhaustive search is also an alternative for Caesar because 26 shifts are easy to list and inspect. N-gram scoring, which evaluates common pairs or groups of letters, can improve recovery for some shorter texts, but its quality depends on the language model and sample. The chi-square method here is deliberately simple and reproducible.

Conclusion

These two schemes illustrate distinct sources of cryptographic weakness. Caesar's weakness is structural: substitution preserves a recognizable language distribution and its key space is tiny. The elliptic-curve example uses strong curve arithmetic but artificially weak key selection and a simplified message encoding. The experiments show why the security of a cryptographic system depends on the complete construction, not only on the name of the algorithm it uses.
